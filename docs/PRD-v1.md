## 1. 产品目标与非目标

### 1.1 一句话定义

> **输入现有用户表 → 用 100 个可复用 Agent 并发槽位逐人调用第三方模型 API → 输出与输入行一一对应的逐人模拟购买意向表。**

### 1.2 口径定义（写死，全团队统一，不得歧义）

| 术语 | 定义 | 禁止的误读 |
|---|---|---|
| **1 万个智能体** | **1 万个独立 persona 的作答任务**；每人独立上下文，正常情况调用模型一次 | 不是 100 个 Agent 各答 100 题 |
| **100** | **并行执行槽位数**（`AGENT_CONCURRENCY=100`） | 不是总样本数、不是机器数、不是进程数 |
| 槽位语义 | 单槽位一次只处理一个用户，完成即领取下一行，**不等待整轮完成** | 禁止"每轮固定取 100 行再等整轮" |
| 总样本数 | = 输入表行数（默认全表），上限 20,000 | 不筛选、不抽样、不由平台生成人群 |
| persona | 输入表一行经列映射后的画像快照 | 平台不生成、不补全、不自动过滤画像 |

**用户数 < 100 时仅占用对应数量槽位。** 第三方配额不足时如实显示限流与实际并发，**不得把 100 个排队任务宣称为 100 个同时在途请求**。

### 1.3 产品目标（3 条，正交）

| # | 目标 | 可衡量标准 |
|---|---|---|
| G1 | 逐行可追溯：输入 N 行 → 输出 N 行，按 `row_no` 排序 | 20,000 行导入零静默丢行；无重复 persona_id |
| G2 | 规模可信：单 worker 内 100 路真实在途并发，任务不依赖浏览器 | 峰值在途 == 100 且始终 ≤ 100；关页/杀 worker 后可恢复 |
| G3 | 结论诚实：只统计有效答案，失败与未知费用不被隐藏 | 五档计数和 == valid；失败行 value 为空；无价格时显示"未知" |

### 1.4 非目标（直接引用主文档 §1.2「默认不做」清单，不新增）

画像生成/补全、模型训练、RAG、向量库、Agent 对话、浏览器仿真、通用问卷编辑器、多租户/计费、自动长篇 AI 报告、Kubernetes。**无需 GPU。**

### 1.5 首版冻结边界（主文档 §1.1）

固定单题（`purchase_intent`）、固定五档、单个内部工作空间、同一时刻一个运行批次、一个 worker 进程、最大 20,000 行、默认全表运行。

## 5. 统计口径（原样固化主文档 §8.3，禁止自创）

```text
planned = run.sample_size
valid = succeeded 成员数
option_rate[v] = count(value=v) / valid
top2box = (count(probably_yes) + count(definitely_yes)) / valid
mean_score = sum(score(value)) / valid
coverage = valid / planned
progress = (succeeded + failed + cancelled) / planned
```

| 规则 | 要求 |
|---|---|
| **valid = 0** | 比率与均分返回 **null**，页面显示 **"暂无有效回答"**（**禁止显示 0%**） |
| 五档计数之和 | 必须恒等于 valid |
| 四舍五入 | 只在展示层做；SQL 聚合保留原始计数 |
| failed 口径 | **不包括**仍处于 `retry_wait` 的成员 |
| 一致性 | summary 与 export 均用一致性读事务；附 `as_of` 与 `report_revision`；首版不缓存聚合 |
| 计算方式 | 禁止用 LLM 计算百分比（ReportService 只做 SQL 聚合） |
| 分组 | 按 run_members 快照字段分组；缺列隐藏该分组；每组另列 planned/valid/coverage |
| 分母 | 失败行不改变分母（`valid`），另列 planned 与覆盖率 |

## 8. 关键假设

1. 上游仓库只作**源码证据 + 少量纯逻辑改编参考**；本项目独立实现，**不启动上游作为交付物**。

4. 首版不做显著性检验/置信区间；万级样本只验证**工程规模**，不能凭规模证明与真人结果一致。
